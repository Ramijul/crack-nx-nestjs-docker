# CrackNxNestjsDocker

## Context
```
nx version: 21.4.0
pnpm version: 10.13.1
os: Windows 11
```

## Commands used:
```
> pnpx create-nx-workspace
> nx add @nx/nest
> nx g @nx/nest:app apps/api
```
## TLDR: 
- **Use WSL2**
    - Do not mount windows file system. Move the code to the distro, instead.
- Add the packages needed by the rust-based native watcher to the dockerfile - `bash, git, inotify-tools, libc6-dev, and build-essential`
- Using a single docker image for all apps will suffice
- Create a separate service that runs the daemon with the command `nx daemon --start`. The service must keep running. Note that NX is configured to run one daemon per nx project.
    - The `.nx` and sockets generated by this service must be shared with all other services
    - The codebase needs to be shared as well with all services, including the daemon
    - Run all other services only after the daemon runs.
- Mount the `/apps` directory, share it with all services
- Mount a volume to share the `/.nx` folder with all services
- Mount a volume to share the `daemon socket directory` with all services
- Set the directory of the daemon socket with the env variable `NX_DAEMON_SOCKET_DIR`, so that you know where to mount the volume. All services need to know where the sockets are!
- Set the env variable `NX_DAEMON=true`. This required in the docker environment for the daemon to run
- Re-build docker on changes made outside of the `/apps` directory
